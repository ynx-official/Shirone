# 首页资源优化

生产性能审计使用 `pnpm build` 生成的 Node SSR 服务，不能用 4322 开发服务分数作生产基线。

- `scripts/shell-assets.mjs` 从原图生成专用 48px favicon，经 Nitro 挂载在 `/_site/`。
- `scripts/images.mjs` 在内容构建时生成带资源签名的 WebP 候选；Banner 保留移动端与桌面构图，卡片及头像通过 `srcset` 选择大小。原图仍留在内容资源中。
- 通用页面入口按实际页面异步加载文章、相册、归档等组件；SSR 仍等待组件输出，禁用 JavaScript 时可读。
- 设置面板的独立 CSS 随面板组件加载，导航和语言选择器样式留在首屏。
- NuxtLink 预取改为悬停或聚焦时触发，避免首屏同时预取所有可见导航项。
- 默认配色直接使用构建时生成的亮暗主题。用户保存的自定义配色或手动调色才需要调色引擎。
- 词典仅在服务器导入，SSR payload 携带当前语言及十种语言名称。切换语言按需请求同源 `/api/i18n`，成功后一起更新词典、语言和 cookie；快速切换忽略过期响应。
- Nitro 为静态资源生成 gzip/Brotli；字体生成目录和 favicon 生成目录不作为服务端内容数据打包。

验证包括类型检查、lint、Node 测试、生产浏览器的首页资源、十语言切换、主题设置、无 JavaScript、路由及无障碍回归。Lighthouse 应串行运行并记录设备、版本、资源体积和指标，避免仅凭一次分数判断收益。

## 2026-09-20 本地生产对比

使用独立构建副本、Lighthouse 12.6.1 默认移动端模拟（150ms RTT、
1638.4 Kbps、4 倍 CPU 降速），优化前后交替串行各跑三轮。
基线已包含上一次的字体子集化，不是开发服务器，也不是原始 15 MB 字体版本。

首屏 LCP 仍未达理想值，不能把体积优化等同于已达 90 分。
